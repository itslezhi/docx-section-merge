# 模板说明的识别、优先级与执行

项目模板中的显式说明是合并结果的**一级强制验收约束**。每次任务都必须从**本次上传的模板**重新识别，不得把之前模板中的字数、分项数量、标点、格式或写法要求硬编码为 Skill 的通用规则。

子文档只提供事实与内容载荷。它的文字即使完整，也必须在不改变技术含义的前提下重组为当前模板要求的长度、结构和表达方式。用户已明确授权的模板例外直接执行并登记；尚未决定的实质冲突按合并契约局部暂停并询问。子文档按模板槽位组织，不改变技术事实，也不免除详细内容保留义务。

## 1. 自动发现模板要求

开始章节映射前先运行：

```bash
python3 scripts/extract_template_requirements.py 项目模板.docx \
  --json template-requirements-candidates.json
```

扫描范围必须覆盖：

- 主文档正文和全部表格；
- 页眉页脚、脚注、尾注和批注；
- 斜体、彩色或括号内的提示文字；
- 内容控件的标题、标签和占位说明；
- 表头、字段名、相邻说明和章节后的写作提示。

自动扫描至少识别以下信号：

- 字数：`N字左右`、`不超过N字`、`不少于N字`、`N字以内`；
- 结构：`分条列出`、`不得分述`、`逐项填写`、`按年度填写`；
- 标点：`分号隔开`、`句号结束`；
- 一致性：`与正文小标题相对应`、`与封面一致`、`前后一致`；
- 内容质量：`量化可考核`、`明确原始基数`、`重点阐述`、`附报告`；
- 格式与版式：字体、字号、字重、缩进、行距、对齐、纸张、页边距、页眉页脚和表格不可改等要求；
- 编号与交付：编号规则、附件、报告、证明材料和提交形式；
- 禁止项与例外：不得修改表格、不得新增层级、仅填指定字段等。

脚本输出是候选清单，不能代替语义审阅。必须再通读模板全部可见文字并逐页渲染检查，补充脚本未解析的自然语言要求或图片/特殊对象中的要求，并确认每条提示的真实作用域。

候选清单实行闭环：每条候选必须标记为 `accepted_requirement`、`duplicate_requirement`、`template_label_or_example` 或 `not_a_requirement`，并记录理由；不得存在未复核候选。自动抽取没有发现的要求由通读与逐页检查补入同一清单。

## 2. 区分提示、槽位和约束作用域

为每条要求同时记录：

1. 提示文字是否必须原样保留；
2. 允许填写的目标槽位；
3. 约束作用于一个字段、一个章节还是整份文档；
4. 约束是否影响格式、内容、编号、引用或交付材料；
5. 验证方式及停止条件。

使用标签、相邻字段和容器路径定位。表格索引只能用于本次冻结后的模板；模板版本变化时重新定位，不能套用旧索引。

### 2.1 有确定依据的跨字段回填

模板槽位缺值时，可在不询问用户的情况下回填**能够唯一确定**的事实，但必须记录来源与映射。证据优先级为：用户本次明确给出的值；同一模板已填写的权威字段（如封面）；用户指定的子文档中一致且无冲突的正式字段；由上述字段进行无歧义格式转换得到的值。典型操作包括把封面已经确定的起止年度或总经费同步到项目基本信息表。

只有同时满足以下条件才自动回填：

1. 目标字段与来源字段语义一一对应；
2. 全部可用来源不存在冲突；
3. 不需要估计、评价、补造或改变技术承诺；
4. 回填后仍满足模板显式说明；
5. 使用目标槽位的局部格式，而不是来源字段或普通正文格式。

不满足任一条件时保留空槽、标注待确认或询问用户。不得把示例值、提示文字、文件名或单一非权威草稿当作确定事实。内部约束记录应写明 `value_source`、`source_location`、`target_location` 和冲突检查结果。

## 3. 编译当前模板专属约束

把已复核要求写入 `template_constraints.json`。每条至少包含：

```json
{
  "id": "stable-rule-name",
  "source_text": "从当前模板提取的原始说明",
  "location": "当前模板中的字段或章节路径",
  "scope": "field | section | document",
  "rule_type": "length | structure | punctuation | correspondence | content | format | layout | numbering | deliverable | prohibition",
  "parameters": "从当前模板解析出的数值、对象或目标关系",
  "validation": "可执行检查或人工复核方法",
  "status": "pending | passed | blocked | superseded_by_user"
}
```

用户已明确覆盖某项模板要求时，原约束标为 superseded_by_user，记录原指令、作用域和替代要求；只对仍适用的要求执行交付门。禁止在 Skill 中预设某个固定字数、固定分项数量或固定标题。所有参数均来自当前模板、当前最终正文或用户本次明确指令。

## 4. 字数口径

工具可以分别计算：

- `cjk_hanzi_count`：Unicode CJK 汉字数量，不含标点、数字、拉丁字母、空格和编号；
- `visible_character_count`：去除空白后的全部可见字符数。

当模板明确写“汉字”或用户指定汉字数量时，使用 `cjk_hanzi_count`。模板只写“字”且未说明口径时，使用 `visible_character_count` 作为主值，并同时报告汉字数，避免口径不明。

从模板动态解析范围：

- `N字左右`、`约N字`：模板未给容差时默认使用 `N±10%`；
- `不超过N字`、`N字以内`：最大值为 N；
- `不少于N字`：最小值为 N；
- 模板或用户给出更精确范围时，以精确范围为准。

字数不足时补充材料支持的实质信息；超出时压缩重复表达。禁止通过缩小字体、压缩字距、改列宽或隐藏文字规避内容约束。

## 5. 结构、标点和对应关系

- `分条列出`：分项数由当前内容决定，编号层级取模板；不能固定为三项。
- `分号隔开，句号结束`：前若干项使用模板指定分隔符，最后一项使用模板指定终止符。
- `与正文小标题相对应`：先完成正文去重、综合和编号，再由最终小标题反向生成摘要；逐项做规范化名称和数量校验。
- `不得分述`：综合为连续文本，不能按子文档数量机械拆段。
- `量化可考核`：检查每项的对象、数量/阈值、条件和验收口径；资料不足时不得编造。
- `相对数值明确原始基数`：同时给出基准对象、基准场景或计算口径；缺失时保留原指标，批注缺少的基数并暂停该项补写；继续其他确定内容，集中向用户询问。
- `与封面一致`：核对字段值，同时保持模板提示及字段格式不变。

一条提示可能同时产生多种约束。例如一个摘要槽位可同时具有字数、分条、标点和正文对应关系；必须全部通过，不能只检查其中一项。

## 6. 写入前后双重执行

1. **写入前：** 对拟写文本执行当前约束，调整内容后再写入模板。
2. **写入后：** 从最终 DOCX 的真实槽位重新提取文本，使用 `scripts/audit_instruction_constraints.py` 或等价检查逐项验收。
3. **反向一致性：** 正文标题、指标、成果或编号变化后，重新运行所有依赖它们的摘要和对应关系约束。
4. **交付门：** `template_constraints.json` 中不得存在 `pending` 或失败的强制约束；无法自动验证的说明必须人工复核并记录依据。

以下命令形态只是调用方式，所有参数都必须由当前模板和当前正文动态填写：

```bash
python3 scripts/audit_instruction_constraints.py 合稿.docx \
  --cell TABLE:ROW:CELL \
  --item-regex '从当前模板确定的分项模式' \
  --count-unit COUNT_UNIT --target TARGET --tolerance TOLERANCE \
  --expected-items FINAL_ITEM_COUNT \
  --intermediate-punctuation '模板规定的分隔符' \
  --final-punctuation '模板规定的终止符' \
  --heading '当前正文的第一个对应标题' \
  --json instruction-audit.json
```

示例文字、变量名和某一模板的要求都不能变成其他项目的默认值。只有完成“自动发现—语义复核—动态编译—写入前检查—写入后复核”，才能声称严格执行了项目模板。
