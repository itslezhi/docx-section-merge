# OOXML 章节移植实现规范

## 1. 不采用的做法

- 不用 `python-docx` 的 `.text` 重建段落；这会丢失公式、域、批注、超链接、修订和复杂格式。
- 不直接把供体 `<w:body>` 子节点追加到主文档；图片、图表、样式和编号关系会断裂或冲突。
- 不使用截图代替表格、公式或可编辑文字。
- 不导入供体末尾 `<w:sectPr>`，除非用户明确要求保留供体节设置。

## 2. 块级抽取

以 `word/document.xml` 的顶层正文块为单位，包括 `<w:p>`、`<w:tbl>`、块级 `<w:sdt>` 和其他实际承载内容的容器。范围边界若落在表格或内容控件内部，必须在对应容器层处理，不能截断 XML 结构。

复制前记录块序列及其所有引用属性：

- `r:id`、`r:embed`、`r:link`；
- `w:numId`、`w:pStyle`、`w:rStyle`、`w:tblStyle`；
- `w:bookmarkStart/@w:id`、批注和修订 ID；
- `wp:docPr/@id`、VML shape ID；
- 脚注、尾注、批注、批注扩展和自定义 XML 引用；
- 域代码、书签名、超链接锚点。

## 3. 依赖闭包迁移

对供体块使用的每个内部 relationship：

1. 解析供体当前 part 的 `.rels`；
2. 复制目标 part 到主包的唯一路径；
3. 递归复制该 part 的 relationships；
4. 在主 part 中创建唯一 `rId`；
5. 重写移植 XML 中相应引用；
6. 合并 `[Content_Types].xml` 中需要的 Default/Override。

这适用于图片、图表、图表样式、嵌入工作簿、OLE、diagram、超链接等。External relationship 保留目标和 External 模式，但在报告中列出。

媒体文件复制后必须与供体做 SHA-256 比较。相同媒体可去重，但不得重新压缩或转码。

## 4. 样式迁移与格式策略

样式不是 relationship 依赖，不能由本节的通用依赖闭包顺便导入。先读取 [模板样式隔离与受控移植流水线](style-isolation-pipeline.md)，把子文档拆成文字载荷、技术对象载荷和综合证据，再选择独立写入路径。

- `template_normalize`：先在供体侧剥离样式引用和直接版式，再调用仅处理 relationship/编号的克隆器，最后应用母版角色原型。
- `payload_preserve`：只复制图片、公式、图表、表格数据或嵌入对象的内部载荷和必要关系，外层容器按母版重建，不导入供体样式。
- `synthesize`：不克隆供体段落，只从母版原型创建。
- `strict_preserve`：仅限用户明确指定的源格式例外，使用样式隔离文件规定的局部样式导入器计算闭包、改名并去除 `w:default`。

禁止实现一个会同时扫描 relationship、编号和样式的无策略 `clone()`，然后在克隆结果上调用 `normalize_paragraph()`。这会在局部清理之前污染目标 `styles.xml`。

## 5. 列表与编号定义

对供体使用的每个 `w:numId`：

1. 找到对应 `w:num` 和 `w:abstractNum`；
2. 复制为主文档中的新唯一 ID；
3. 迁移图片项目符号等关联资源；
4. 重写供体块中的 `w:numId`；
5. 根据最终章节编号策略决定保留供体列表值，还是只修改标题编号。

不要把正文列表编号误当成章节号整体重排。

## 6. 全局唯一 ID

至少重映射：

- relationship ID；
- drawing `docPr` ID；
- bookmark ID 与冲突的 bookmark name；
- comment、footnote、endnote ID；
- numbering/abstract numbering ID；
- style ID 冲突；
- VML shape 与对象 ID。

若书签名改变，必须同步修改 `REF/PAGEREF` 域和内部超链接锚点。

## 7. 插入与删除的提交顺序

1. 复制主文档为临时输出；
2. 在临时输出中导入供体依赖闭包；
3. 校验所有新 relationship 目标存在；
4. 插入供体块到临时位置并验证可打开；
5. 删除主文档目标范围；
6. 把供体块移动到最终锚点；
7. 执行编号和引用更新；
8. 结构审计、保存、渲染；
9. 全部通过后把临时输出提升为最终文件。

发生异常时丢弃临时输出，从原始主文档副本重来。

## 8. 模板固定表单的内容槽位

固定表格不得使用普通块移植逻辑。禁止删除目标单元格除 `tcPr` 外的全部子节点，再追加供体单元格子节点；这种做法会把供体段落/运行格式、额外段落、制表符和换行带入母版。

正确做法：

1. 冻结母版 `tblPr/tblGrid/trPr/tcPr` 和每个可写槽位的 `pPr/rPr` 骨架；
2. 只替换获授权槽位中的文本或内容对象；
3. 新文本使用母版运行骨架，保留模板段落数量；
4. 写入后运行 `scripts/audit_template_format.py`；
5. 如内容必须新增段落或改变行高，先取得明确授权，并把该单元格列为格式契约例外。

## 9. 图片版心适配

在克隆图片段落前，计算目标容器的 `layout_envelope`：页面可用宽度取 `pgSz - pgMar`；图片位于表格单元格时，再扣除表格网格宽、单元格边距及段落缩进。分别检查 DrawingML 的 `wp:extent`、`a:xfrm/a:ext` 与 VML `style` 中的显示尺寸。

- 未超出可用范围时保留原显示尺寸和锚定；
- 超出时按同一比例缩小全部相关尺寸，保持媒体字节、`srcRect` 裁剪参数和宽高比不变；
- 不得只改 `wp:extent` 而遗漏内部变换尺寸，也不得按目标宽高分别缩放；
- 对悬浮对象保留 `relativeFrom`、wrap、z-order 和对象相对顺序，校正后仍漂移或遮挡时才请求转换为内嵌对象的授权；
- 合并后逐图核对图片与题注相邻关系、页面边界、清晰度和无拉伸状态。

## 10. 已知限制

复杂 SmartArt、ActiveX、宏、受保护内容、链接图片、第三方引用管理器字段和损坏 OOXML 可能无法通用迁移。遇到这些对象时，不将“Word 能打开”视为成功；必须验证依赖闭包和实际渲染，必要时请求用户提供已转为普通嵌入对象的版本。
