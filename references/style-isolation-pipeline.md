# 模板样式隔离与受控移植流水线

本文件负责解决一种全局性故障：供体段落看似已经“按模板规范化”，但它的样式依赖先被导入了合稿，进而改变模板原有字段、标题或其他未编辑区域的显示。格式正确性必须由移植路径保证，交付审计只作为最后一道门。

## 1. 根因模型

DOCX 的格式不是段落局部属性的简单集合。一个运行的最终外观可能依次来自：

1. 运行直接属性 `w:rPr`；
2. 字符样式 `w:rStyle` 及其 `basedOn` 链；
3. 段落直接运行属性；
4. 段落样式及其 `basedOn` 链；
5. `docDefaults`、默认字符/段落样式、主题和字体替换。

因此，以下顺序是错误的：

```text
深复制供体块 → 自动导入全部样式依赖 → 删除 pStyle/修改字体和缩进
```

删除局部样式引用发生得太晚。供体 Normal、Default Paragraph Font、Normal Table 或 `Strong` 等样式已经进入目标 `styles.xml`：

- 第二套 `w:default="1"` 会改变模板中没有显式格式的未编辑字段；
- 残留 `w:rStyle` 会覆盖已清理的直接属性，例如参考文献编号通过 `Strong` 继承加粗；
- 同名样式、主题字体或 `basedOn/next/link` 依赖会把污染扩散到未直接复制的区域。

不能通过给异常字段补空格、负缩进、显式字体或逐个取消加粗来修复。这会把一个全局依赖错误变成大量脆弱的局部补偿。

## 2. 在代码层分离内容载荷与格式

子文档默认只提供内容载荷，母版提供全部外层格式。每个待写入块先标明载荷类型，再调用对应 API；禁止使用一个“通用 clone”把内容与供体格式一起搬入。

| 写入路径 | 允许导入供体样式 | 正确写入方式 |
| --- | --- | --- |
| `template_normalize`（文字与可编辑文本） | 不允许 | 在任何依赖导入前剥离供体样式和直接版式，只迁移文字/关系，再应用母版角色原型 |
| `payload_preserve`（图片、公式、图表、表格数据、嵌入对象） | 不允许 | 保留对象内部载荷与语义，把对象放入母版承载段落/表格并按模板适配 |
| `synthesize` | 不允许 | 从母版同角色段落、表格或题注原型创建，只把研究材料作为事实证据 |
| `strict_preserve`（用户明确指定的源格式例外） | 允许所需局部样式 | 仅复制实际可达样式；冲突样式改唯一 ID；每个复制样式删除 `w:default`；依赖闭合 |

固定表单再使用独立的 `write_fixed_slot` 路径，只改模板既有文本槽位，不能调用正文移植 API。

### 2.1 `template_normalize`

按以下顺序执行：

1. 在内存中深复制供体块，尚不访问目标包。
2. 先识别公式、OLE、图片、图表和技术表格；把对象内部载荷拆出并交给 `payload_preserve`，不把供体承载段落和表格文字格式一并复制。
3. 对普通文字运行 `scripts/style_firewall.py` 的 `detach_normalized_fragment()`：删除 `pStyle/rStyle/tblStyle` 和供体段落布局；默认只保留上下标、语言和校对等语义属性。
4. 仅当字符样式确实表达语义时，显式列入 `semantic_character_styles`。函数只把它的有效粗体/斜体转换成直接属性，不复制该字符样式。
5. 对返回片段运行 `assert_no_style_references()`；未通过时不得进入目标包。
6. 迁移图片、超链接、嵌入对象等 relationship 和获授权的编号定义；依赖导入器不得顺便扫描或复制样式。
7. 根据段落角色绑定并深复制冻结的母版 `pPr/rPr` 原型。标题、正文、编号正文项、列表标题、题注、公式行、表格字段和参考文献分别映射；禁止用硬编码字号/字体重建所谓“统一正文”，也禁止在原型依靠继承时擅自新增直接格式。
8. 片段进入目标包前运行原型差异门：除登记的语义属性外，新增直接格式必须与绑定原型一致；未绑定原型或出现越界直接格式时立即拒绝该片段。

把源段拆成标题与正文、补齐缺失标题或改变编号层级，都不能在第 7 步之外额外写入 `bold=True` 等字符强调。结构处理与角色格式必须解耦；只有母版同角色原型或用户明确指令能够授权粗体。

关键约束：必须“先隔离、再导入”。不得先调用会自动导入 `pStyle/rStyle/tblStyle` 的克隆器，再在结果上删除样式。

### 2.2 `payload_preserve`

技术对象“原样保留”只指内容载荷，不表示供体段落、字符或表格样式成为格式权威：

- 图片：媒体字节、裁剪和宽高比保持不变；重新放入母版图片段落，尺寸受目标版心或单元格约束，题注使用母版题注角色。
- 公式：保留 `m:oMath`、OLE 数据和公式内部语义格式；外层段落、对齐、段距和编号使用母版公式角色，不复制供体 `pStyle/rStyle`。
- 图表/嵌入对象：复制对象 part 及 relationship 闭包，外层锚点、题注和版心适配服从模板。
- 表格：保留单元格文字、数值、公式、必要合并关系和技术数据；表格样式、边框、单元格边距、表内文字和题注映射到母版同类表格。没有可复用原型时，以母版默认表格角色新建，不导入供体表格样式。
- 表格定位属于外层格式。除非母版同角色原型明确使用浮动表格并完成跨编辑器验证，否则在进入目标包前删除供体 `w:tblpPr`、环绕和重叠设置，使技术表格按正文流内嵌排版；再由分页规则决定题注、表格与后文的关系。
- 技术表格回到正文流后，继续绑定 [格式规范化](format-normalization.md) 的 `technical_table` 角色；不能保留供体对齐，也不能因未设置 `w:jc` 而默认为左对齐。

该路径的 `imported_styles` 必须为空。若对象无法与供体外层样式分离，停止并说明限制；不能因此自动升级为保留整块源格式。

### 2.3 `synthesize`

综合章节不复制任何供体段落或供体样式。先建立证据映射，再深复制母版角色原型并替换文本；新图按图件规范生成。引用供体公式、图片或表格时，只把对象内部载荷交给 `payload_preserve`。

### 2.4 `strict_preserve` 显式例外

只有用户明确点名某个范围并要求连供体排版也保持不变时，才按实际使用关系计算样式闭包，逐项复制并重映射：

1. 目标不存在且不会冲突时仍使用唯一内部 ID；存在同 ID 不同定义时必须改名。
2. 每个复制样式必须通过 `localize_imported_style()` 删除 `w:default`。
3. `basedOn/next/link` 指向供体默认样式时：定义与母版默认样式规范化等价才可映射到母版；否则复制为唯一的**非默认**局部样式。
4. 供体主题色/主题字体必须转换为局部显式属性或封装在独立非默认样式中；不得替换母版主题。
5. 完成后断言默认段落、字符、表格样式仍只有母版各一项。

### 2.5 固定表单

固定表单从母版节点原位编辑：

- 定位到授权槽位中的现有 `<w:t>`；
- 保持 `tblPr/tblGrid/trPr/tcPr/pPr/rPr` 和段落/运行数量；
- 不从供体复制 `<w:tc>`、段落、运行或样式；
- 未授权字段连相同文字也不重建。

新增值或段落必须使用 [格式规范化](format-normalization.md) 中的固定表格语义角色。固定槽位 API 必须分离两套原型：目标单元格只提供段落数量、对齐、缩进、行距等位置布局；母版的共享 `fixed_table_value` 原型提供正式值的字体、字号、字重、正斜体和语言。不得把填写说明当成正式值原型，也不得只清除说明斜体后继续保留其仿宋/楷体或不同字号。更不得把正文统一字号写入表格槽位，或因为原型未显式写 `w:sz` 就中断其样式继承。

如果固定字段的局部 XML 与母版相同却显示变化，首先停止并检查全局样式、主题和字体表；这通常不是该字段需要局部修补。

## 3. 模板格式事务

每次合并都以母版快照开始，在临时包中执行，并经过提交门后才产生最终文件。

### 3.1 冻结母版全局状态

至少冻结：

- `styles.xml/docDefaults`；
- 母版默认样式的类型、ID 和完整定义；
- 母版全部既有样式定义；
- `theme1.xml`、`fontTable.xml`；
- 固定表单的表格、行、单元格、段落和运行骨架；
- 模板标题及其他未授权区域的格式指纹。

默认合并不应新增供体样式。只有登记过的 `strict_preserve` 显式例外可以新增非默认局部样式，且不得修改上述母版状态。

### 3.2 分批提交门

每迁入一份子文档或一类复杂对象后，先把临时结果写出，再运行：

```bash
python3 scripts/style_firewall.py 项目模板.docx 临时合稿.docx --json style-gate.json
```

命令失败时立即废弃临时结果，从最近一个通过的模板副本重新处理该批；不得在污染后的最终文件上逐字段补救。这样既阻止坏结果交付，也能定位是哪一份供体、哪一类片段首次越过边界。

交付前再运行 `audit_template_format.py` 检查固定表单和角色格式。前者负责全局样式隔离，后者负责局部格式、参考文献和表格骨架，两者职责不能互相替代。

提交门分为两层：片段级原型差异门阻止错误格式进入目标包；批次级 `style_firewall.py` 阻止全局样式、主题和默认值污染。只做后一层不能发现“在局部运行中写死字号覆盖模板继承”的错误，两层都必须通过。

## 4. 参考文献的生成规则

参考文献条目全部走 `template_normalize`：

1. 以母版参考文献原型或统一角色建立段落；
2. 将 `[n]` 视为结构标记，而不是供体强调，清除其 `rStyle` 并使用母版编号运行原型；
3. 作者、标题、年份等普通片段使用参考文献正文原型；
4. 期刊名等确有语义的斜体先解析为语义，再以直接斜体或母版强调样式重新应用；
5. 不因样式名称叫 `Strong` 或 `Emphasis` 就自动认定其格式有语义；
6. 从第一条到最后一条计算有效字体、字号和字重，不能只看直接 `<w:b>`。

这会从生成源头避免“前一批编号加粗、后一批不加粗”，而不是在最终稿里寻找异常编号逐个取消。

## 5. 格式溯源记录

内部记录每个写入块的：来源文件、章节、策略、目标角色、是否导入关系/编号/样式、导入样式 ID、角色原型指纹和提交门结果。至少满足：

- `template_normalize`、`payload_preserve`、`synthesize` 的 `imported_styles` 为空；
- 只有用户明确登记的 `strict_preserve` 例外可以出现导入样式，且每个样式均为非默认并有唯一 ID；
- 固定表单的来源始终为 `template_slot`；
- 固定表单正式值均登记同一个 `fixed_table_value` 字符原型，并保留各自目标单元格的位置布局原型；
- 任一格式门失败都不提升为最终文件。

该记录用于定位和复现问题，不作为对失败输出的修补清单。

## 6. 禁止模式

- 先 `target.clone(donor_block)` 自动导入样式，再调用 `normalize_paragraph()`；
- 在 `template_normalize` 中保留未知 `rStyle`，同时只删除直接 `w:b/w:i`；
- 把整份供体 `styles.xml`、`docDefaults`、主题或字体表并入母版；
- 发现未编辑字段漂移后添加空格、负缩进、字符位置或额外运行进行补偿；
- 用正文规范化函数创建固定表单内容；把占位说明的字体、字号、斜体或颜色复制给实际值；或让不同正式值各自继承相邻说明而产生角色分裂；
- 保留供体浮动表格定位，导致题注与表格分页分离或后文绕排；
- 在污染文件上继续迭代并把最终审计当作清理器；
- 仅检查固定字段局部 XML，不检查它实际依赖的全局样式链。
