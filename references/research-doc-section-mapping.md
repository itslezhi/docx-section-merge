# 子文档与模板章节映射

命名约定：泛指输入类型时使用“子文档”；需要区分具体来源时统一使用“子文档A、子文档B、子文档C……”作为示例名，不使用项目特定的“研究内容一/二/三”等称谓。

## 1. 文件与章节

以用户本次说明和正文正式名称确定研究项与顺序。一份稿件可以包含多个研究项，文件名和上传顺序只辅助判断。所有实质子文档均进入 research_docs；模板单独登记。

从母版建立 canonical_sections：章节标题、层级、容器、前后锚点、可写/可重复槽位、提示约束和角色原型。模板哈希变化后重新定位，不能复用旧容器序号。

## 2. 完整盘点与矩阵

先运行 v3 inventory，再检查每份稿件在目的意义、现状、目标、指标、验证、主要内容、关键技术、创新、总体方案、成果、进度等模板适用章节中的内容。盘点包括表格、文本框、公式、图表、脚注、尾注、源批注和独立对象。

章节矩阵回答“某子文档是否为某模板章节提供内容”；源块登记回答“每一块原文最终去哪里”。两者不能互相代替。矩阵不适用不能成为整份输出遗漏源块的理由。

每个源单元恰有一条 content_register。以 [合并契约](merge-contract.md) 的 retention 表确定处置；用独立 uses 记录总体综合用途。弃用旧计划的 synthesis_evidence 删除状态与 matrix_exceptions 删块机制。

## 3. 按模板组织

| 模板章节特点 | 组织方式 |
| --- | --- |
| 连续论述 | 按背景、已有工作、缺口等关系排序，保留完整实质段落 |
| 明确要求整体目标或不得分述 | 在模板限定槽位综合，并保留其他应保留的详细材料 |
| 并列研究内容或关键技术 | 按正式研究项分组，层级格式取母版 |
| 指标、成果、考核清单 | 严格重复/授权替换后连续编号，独立承诺全部保留 |
| 验证章节 | 对应最终每项指标与验证条件 |
| 总体方案 | 仅在契约允许的范围综合各研究项，不把某一局部方案冒充总体方案 |

## 4. 标题补齐与结构调整

补标题优先使用用户正式名称、模板要求对应的权威标题、同稿一致的正式名称。已有一致依据时补齐结构并加真实批注；有多个不改变技术含义的合理标题时可给出建议并批注。证据不足则保留原结构，列出待裁定项，继续其他内容。

源稿标题和正文在同一段、且边界可由标点和上下文确定时可拆分；登记 structural_changes，重组后字词、标点和对象保持一致，必要新增衔接单独登记。模型提出的结构需对应批注。

补齐、拆分和重编号不授权加粗或换字体。所有新段绑定母版同角色原型，没有母版依据就不硬编码强调。

## 5. 位置与顺序

源稿局部“总体方案”保留在所属详细内容；模板需要项目总体章节时另外依据多稿综合。若局部内容改置到关键技术或实施途径，明确记录原章节、新章节与理由并锚定批注。不重复搬运同一详细正文来逃避位置裁定。

内容排序依据用户顺序、模板要求和有证据的论述关系。文件边界不自动产生标题、分页或编号重启。语义无法确定时按契约分级处理，不将一般结构歧义升级为整项任务阻塞。

## 6. 验收

全部源单元自动盘点、逐章审查、目标存在；每处原文保留及综合用途可分别追溯；结构调整有依据与批注；编号与对象位置正确。运行新版 verify_coverage.py，并完成机器不能替代的语义和视觉核验。
