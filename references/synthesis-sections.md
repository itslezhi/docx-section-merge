# 总体性章节综合编制

## 1. 触发边界

触发权限以 [合并契约](merge-contract.md) 为准：用户明确授权，或当前模板明确要求在指定槽位形成总体表述/摘要时使用 `synthesize`。典型对象包括总体技术方案、总体目标、总体技术路线说明和综合验证框架。用户只要求无损移植时不得自动综合。

总体章节必须覆盖合并计划中全部适用的子文档；研究内容数量和正式名称以用户上传文件为准，不设固定值。

## 2. 证据映射

为每个适用研究内容建立 `synthesis_evidence_map`，并写入对应源条目的独立 `uses`；保持其原文 `retention` 不变：

| 字段 | 内容 |
| --- | --- |
| research_item | 正式研究内容或技术主题 |
| problem | 要解决的问题 |
| input | 输入对象、状态和条件 |
| method | 核心方法或机制 |
| output | 模型、指标、算法、系统或成果 |
| relation | 与其他研究内容的先后、输入输出、约束、反馈或并列关系及证据 |
| validation | 对应验证方式和判据 |
| research_doc | 子文档、章节和块位置 |

关系必须有材料支持。资料只支持并列时写并列协同；不得为了叙述完整虚构接口、闭环、依赖、反馈或量化承诺。

## 3. 综合正文工作流

1. 汇总每个研究内容的对象、问题、方法、输出和验证；
2. 在指定综合槽位组织论述；详细源文的处置另按合并契约判断，不能因用于综合而删除原文；
3. 识别有证据的共性基础、研究内容关系、集成方式和验证闭环；
4. 形成“总体目标—各研究内容任务—关键方法—集成关系—验证”的覆盖提纲；
5. 使用 `research-project-document-v2` 只编写获授权的总体章节；
6. 对照证据映射逐句核验；
7. 按模板正文角色写回，禁止复制任一子文档的局部格式。

启用批注模式时，在综合章节首个实质段落添加 `[综合编写]` 批注，说明证据覆盖范围。若源稿中的局部“总体技术方案”被保留但重新安置到该研究分项的关键技术、实施途径或其他模板章节，在迁移后的分项标题上添加 `[位置调整]` 批注，注明原章节、目标章节和调整理由，请人工最终裁定；不得为了避免批注而重复复制该内容。

总体正文必须回答：各研究内容分别做什么，彼此如何共同支撑项目目标，最终如何验证。它不能由局部方案按文件顺序首尾相接，也不能偏向某一子文档而遗漏其他适用内容。

## 4. 写作约束

- 术语、对象、指标口径与各研究内容的规范版本一致；
- 已在研究内容章节详述的内容只作必要概括，不整段复写；
- 衔接语表达已证实的逻辑关系，不用空泛套话代替关系；
- 量化指标只引用最终唯一指标清单；
- 每个综合结论都能回溯到一份或多份子文档；
- 总体章节以整体项目为主语，不以某一子文档为主语。

## 5. 与总体图的衔接

需要总体架构图或路线图时，先冻结本文件产生的术语表、节点表和关系表，再调用 [图件生成与修复](diagram-generation-repair.md)。正文与图必须共享同一组研究内容名称、输入输出和关系，不得分别推断。

## 6. 验收

- 每个适用研究内容至少在总体目标、任务关系和验证链中取得合理位置；
- 没有子文档不支持的新事实、接口、关系和指标；
- 没有局部“总体方案”被整段直接冒充最终总体方案；
- 没有重复抄写已在研究内容章节完整保留的内容；
- 逐句证据映射完整，项目模板格式角色无漂移。
- 批注模式下，综合编写与局部总体方案重定位均有真实 Word 批注且与证据映射一致。
