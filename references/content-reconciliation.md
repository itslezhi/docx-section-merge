# 内容保留与删除证明

授权、retention 状态及歧义分级统一以 [合并契约](merge-contract.md) 为准。本文件只描述执行证据。

## 1. 先盘点再处置

使用 v3 inventory 从每份原始 DOCX 枚举全部内容单元，默认 preserve。不要先提取选中章节再把它作为“全部源稿”。每条记录包含源文件身份/哈希、真实 source_block、目标章节、retention、targets 和独立的 uses。

源稿的表格骨架与表内内容分别枚举。仅作为排版容器的表格骨架可按契约登记 container_layout；表内每段文字、公式和对象仍有单独去向。空段只在确无文字、公式、域、引用或对象时作为空排版单元。

## 2. 完全重复

只有同一目标章节、相同角色的候选才进入判重。核对字词、标点、单位、阈值、限定词、否定、引文、段落顺序、公式结构、图片与裁剪、表格拓扑/数据及所有对象依赖。不能屏蔽引文或图号后证明重复。

v3 校验器从两个实际源单元重新计算内容与对象签名。保留实例必须为 preserve，删除项 covered_by 指向它；不允许删除链和循环。若是一组段落重复，逐单元建立对应并核对组边界、顺序与角色，不能只核对其中一句。

较短、主题相近、部分重叠、互補、被长稿包含或有另一份“完整版本”，均继续保留。颜色、修订作者、文件名、上传顺序只辅助定位，不授权删除。

## 3. 授权简写替换

记录用户实际指令和决议来源、授权文件/章节范围、完整替代实例以及混合段落中的独有信息。存在独有技术信息时先拆出保留；不能安全分离则保留原文并暂停这一个删除决定。

简写删除后在授权范围进行负向检索，记录命中位置与解释。机器门另外检查完整源单元是否仍在未映射的输出位置残留，不能仅修改 retention 就声称删除。模板确需保留的相同摘要单元用 allowed_residual_targets 指定真实 block_id、reason、template_constraint；相同文字在模板要求的摘要中仍可能合法存在，不能用全篇零命中删除摘要。

## 4. 综合与保留

retention 与 uses 分开。例如一段详细技术方案保留到关键技术章节，同时为总体技术方案提供证据：retention=preserve，targets 指向详细段落，uses 指向总体段落并解释支持关系。

模板摘要压缩不解除详细正文保留义务。只有模板确实要求的特定槽位，且该单元没有另外的详细保留义务，才登记 template_condensed；保存模板原始说明、目标和逐句证据，交语义审查。

冗余导语也要记录。源稿“技术指标：”等结构标签与模板父标题重复时，作为结构映射处理；不能把含事实的引导句直接删掉。新增衔接须独立登记与批注，不借衔接语补造关系。

## 5. 反向验收

运行 verify_coverage.py，从冻结源文件重新枚举清单并与登记表逐项比较。漏登、重复登记、未知源块、缺失目标、未授权删除均失败。

再核对原文完整位置、源段重排的逻辑、每处删除证明、原稿已有批注/脚注及综合证据。按源单元对应位置检查图片、公式与表格数据，不用全局数量或少量必含句代替。
