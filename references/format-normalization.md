# 母版格式权威与角色规范化

## 1. 为什么会出现“看似多了空格”

DOCX 中视觉空白不只来自文字里的空格，还可能来自：

- `w:ind` 的首行、左侧或悬挂缩进；
- `w:spacing` 的字符间距或段前段后；
- `w:jc="distribute"/"both"` 的分散/两端对齐；
- 表格单元格垂直居中后，同一行被其他单元格的额外段落撑高；
- 固定行高、单元格边距、网格宽度或字体替换；
- 供体样式与母版同名但定义不同，或供体样式已经进入全局继承链。

因此不能只搜索普通空格。必须比较母版与合稿对应区域的 `<w:tblPr>`、`<w:tblGrid>`、`<w:trPr>`、`<w:tcPr>`、`<w:pPr>`、`<w:rPr>`、段落数、有效样式继承和实际渲染。供体样式如何在写入前隔离，由 [模板样式隔离与受控移植流水线](style-isolation-pipeline.md) 统一规定，本文件不重复定义移植算法。

## 2. 格式权威矩阵

| 内容角色 | 结构权威 | 外观权威 | 内容权威 |
| --- | --- | --- | --- |
| 固定表单、基本信息表 | 母版 | 母版 | 用户事实/获授权供体字段 |
| 模板标题与提示文字 | 母版 | 母版 | 母版 |
| 规范化正文 | 母版章节 | 母版正文角色 | 供体语义 |
| 标题、分项、题注 | 母版层级 | 母版对应角色 | 供体标题语义/最终对象 |
| 公式、符号、上下标 | 供体对象载荷 | 母版承载段落；保留公式内部语义外观 | 供体 |
| 图片、图表 | 供体媒体/数据载荷 | 母版图片段落、题注和版心适配 | 供体 |
| 表格内技术数据 | 母版目标容器或获授权新表 | 母版同类表格及表内文字角色 | 供体 |
| 参考文献 | 母版章节 | 统一参考文献角色 | 文献条目与重编号结果 |
| 用户明确指定的 `strict_preserve` 例外 | 母版目标容器 | 供体局部 | 供体 |
| 综合章节/新图 | 母版章节 | 母版/图件规范 | 证据映射后的综合结果 |

供体排版只能在用户明确点名的 `strict_preserve` 例外中成为权威。其余情况下，供体的缩进、颜色、字体、字号、字距、对齐、段距及表内文字格式只是源稿状态，不得自动继承。“保留文字、图片、公式或表格”只指内容载荷，不表示保留供体排版。

## 3. 固定表单的安全写入

固定表单采用“模板骨架 + 内容槽位”，禁止“供体整格替换”。

1. 冻结母版表格的 `tblPr`、网格列宽、行列/合并拓扑、行属性、单元格属性、段落数、段落属性和运行格式骨架。
2. 用标签、行列网格位置和相邻字段共同识别可写槽位；不要只按 `table_index` 猜测。
3. 标量字段只替换模板现有 `<w:t>` 或在同一模板运行骨架中重建文字。
4. 不复制供体 `<w:pPr>`、`<w:rPr>` 或整个 `<w:tc>`；不使用会清空并重建单元格格式的 `.text` 写法。
5. 不新增段落、制表符、软换行、空白运行或字符间距，除非模板槽位本身如此。
6. 模板原有文字未被授权替换时，整个段落及其运行 XML 必须保持不变，不能把相同文字重新键入或重建；“与封面一致”等短字段应做逐段规范化 XML 对比。
7. 填写后对模板拥有的所有非文本属性做规范化 XML 比较，并并排渲染检查。

### 3.1 固定表格的语义角色

固定表格中的文字至少区分四类：`field_label`（字段名）、`instruction_prompt`（填写说明）、`placeholder`（待替换占位）和 `actual_value`（正式填写值）。它们即使位于同一单元格，也不能互相冒充格式原型。

固定槽位的格式必须拆成两套来源：

- **位置布局原型**：来自目标单元格本身，负责段落数量、对齐、缩进、行距、换行和单元格位置；
- **正式值字符原型**：来自母版中已填写的同类 `actual_value`。若母版没有现成正式值，先从同一表格的中性正式文字角色推导一个共享 `fixed_table_value` 原型，通常采用字段名或中性表格文字的有效中文字体、字号、字重和正斜体；不得从填写说明推导。

所有同级正式值槽位必须绑定同一个 `fixed_table_value` 角色。填写说明中的仿宋、楷体、斜体、颜色、字号等可能都是**说明角色的完整外观**，不能只清除斜体后继续沿用其字体或字号。例如“主要研究内容”“项目关键技术”“技术指标”等并列槽位的正式值，应具有一致的有效中文字体、字号、字重和正斜体，除非母版明确给出了不同的已填写值样例。

### 3.2 目标位置格式级联

固定表单中的新增值或新增段落不得套用“全篇正文默认格式”。先给目标槽位建立局部格式原型，按下列顺序取值，命中后即停止：

1. 目标槽位中可复用的同角色 `actual_value` 段落与运行；
2. 同一表格中最近的同角色 `actual_value` 实例；
3. 母版其他位置的同类表格、同类正式值实例；
4. 母版段落样式、表格样式和 `docDefaults` 共同计算出的有效格式；
5. 母版确无正式值样例时，从同一表格的中性正式文字角色登记并推导共享 `fixed_table_value`；仍无法推导时才采用经用户确认的常规格式。

必须比较**有效格式**，而不只比较直接 XML。字号、字体、字重和斜体可能由段落样式、表格样式或默认样式继承；原型没有直接 `w:sz` 时，应保留继承关系，不能为了“明确”而写入正文统一字号。例如母版槽位通过默认样式得到五号字，新增段落也应继续继承五号字，不能被正文小四号覆盖。

因此，不能把“复制提示运行的全部 `rPr` 后清除斜体”或“调用正文规范化函数”当成固定槽位写入。写入 API 应显式接收 `slot_layout_prototype` 与 `fixed_table_value_prototype`；前者只供应位置布局，后者供应字体、字号、字重、正斜体和语言等字符属性。提交前必须验证全部正式值的有效字符格式与共享角色一致。

### 3.3 原型绑定写入门

模板权威不能只是一条审稿原则，必须落实为写入 API 的前置条件：

- `write_fixed_slot`：只允许修改授权文字节点；必须同时绑定目标位置布局原型和正式值字符原型，禁止继承说明文字角色，禁止写入正文格式常量；
- `write_role_block`：要求提供来自本次母版的 `paragraph_prototype_id` 和 `run_prototype_id`，深复制原型的 `pPr/rPr` 与继承关系后再换入内容；
- `write_payload_object`：只导入图片、公式、图表或表格数据载荷，外层容器仍绑定母版原型；
- 任何没有母版原型且未登记例外的块都不得提交。

每个写入块生成后立即做原型差异检查，而不是等最终稿再发现：除上下标、语言、公式内部格式及已登记的语义强调外，新增的直接 `w:sz`、`w:rFonts`、`w:ind`、`w:spacing`、`w:jc`、`w:b`、`w:i`、颜色和字距必须与所绑定原型一致。原型依靠样式继承而没有直接属性时，输出也不得擅自添加该直接属性。发现越界立即丢弃该写入批次，从干净模板状态重做。

禁止在项目合并器中定义“所有正文恒为 12 磅/某字体”之类的全局格式常量。即使它恰好与某一份模板相同，也会在表格、题注、参考文献或下一份模板中造成越权覆盖。格式数值只能来自本次母版的角色原型或用户明确批准的例外。

### 全局样式边界

固定表单写入前先启用 [模板样式隔离与受控移植流水线](style-isolation-pipeline.md)。它负责冻结母版全局状态、在导入前剥离普通内容及技术对象外层的供体样式，并把用户明确指定的源格式例外限制为非默认局部样式。固定字段局部 XML 与母版一致但显示仍漂移时，必须判定为全局格式事务失败；不得继续对字段添加空格、负缩进或手工位置补偿。

如果真实内容确实无法在模板槽位中容纳，应先报告并选择缩短显示值、使用模板允许的续页/附表或取得改表授权，不能静默缩字、改列宽或撑高相邻字段。

## 4. 段落角色，不做全局“一刀切”

先从母版抽取角色样本和格式指纹：

- `major_heading`、`section_heading`、`subheading`；
- `body`；
- `numbered_item`、`nested_item`；
- `caption`、`table_text`、`formula_line`；
- `template_instruction`；
- `bibliography_entry`。

每个新增段落先按语义用途分类，再映射到同一角色。编号前缀本身不是角色：`（1）某项指标……；` 可以是编号正文项，`（1）某方法研究` 也可以是分项标题。不能仅凭正则匹配到编号就统一当成标题/列表，也不能把“正文首行缩进两字符”施加到标题、分项标题、题注、公式行、表格字段或参考文献。

结构识别与字符强调必须分开决定。把标题从正文中拆成独立段、补齐缺失标题、添加编号或改变层级，都不构成新增粗体、斜体、字号或字体的依据。字符外观仍按母版同级角色原型确定；母版没有同角色加粗实例且用户没有明确要求时，输出不得硬编码 `w:b`/`w:bCs`，应沿用母版基准角色的常规字重。不得把“标题通常应加粗”作为替代证据。

### 正文首行缩进

当用户或母版要求正文首行缩进 2 个汉字时：

- 对普通 `body` 和母版中承担正文陈述功能的 `numbered_body_item` 设置 `w:firstLineChars="200"`；
- 清除与之冲突的 `w:firstLine`、`w:left`、`w:hanging` 和供体直接缩进；
- 标题后第一段也执行同一正文规则，除非母版明确例外；
- 真正的编号标题/列表标签、标题、图题、表题、参考文献和表格字段不套用该规则。

不要用两个普通空格或全角空格模拟首行缩进。

审计时必须把**母版正文原型的完整 `w:ind` 属性集**作为期望值，而不是用通用假设反推。若母版原型同时含有 `firstLineChars="200"` 与兼容用的 `firstLine="480"`，候选正文应原样继承这组属性；不得把母版自身的兼容属性误报为冲突，也不得擅自删除。只有母版原型没有而候选新增的缩进属性，才属于越权直接格式。

### 字体与字符格式

- 中文字体、字号、颜色取母版对应角色；
- 拉丁字母、数字和西文标点使用母版指定西文字体；用户明确要求时统一为 `Times New Roman`，同时设置 `ascii`、`hAnsi` 和需要的 `cs`；
- 数学公式、上下标、符号字体和代码字体不被正文字体覆盖；
- 普通正文不得保留供体的校改红色、随机加粗或错误字距；真正具有语义的强调先列入白名单。

### 参考文献

参考文献必须使用一个统一角色：编号位置、悬挂/首行缩进、段距、行距、中英文字体和字号一致。英文及拉丁片段使用母版参考文献角色规定的西文字体；只有母版或用户明确要求时使用 `Times New Roman`。中文片段使用母版规定中文字体。不得让不同供体的参考文献样式并存。

- 文献编号本身也属于参考文献角色。以母版样例或用户指定为准，统一编号的有效粗体、字体、字号和字符样式；没有母版样例且用户未要求强调时，编号使用常规字重。
- 编号运行与期刊名强调的样式隔离和重建顺序按 [模板样式隔离与受控移植流水线](style-isolation-pipeline.md) 执行。本文件只规定最终角色外观；检查时仍须沿字符样式、段落样式、`basedOn` 和 `docDefaults` 计算有效字重。
- 期刊名等有语义的斜体可以保留，但不得借此保留编号的粗体字符样式。

## 5. 编号段落与正文的边界

- “（2）某技术方法研究”这类行属于分项标题，不按普通正文缩进；
- 其后的说明段才应用正文首行缩进；
- “1）子问题分析”这类行若是下一级标题，必须与同级标题使用相同格式；
- 一段中同时包含“技术指标：”和多个编号项时，先拆成独立规范项或删除冗余导语，再应用编号角色，不能靠空格和手工换行对齐。
- 标题的 `w:left`、`w:firstLineChars` 和正文首行缩进必须分开判断。模板标题已有左缩进时原样保留；不得因“正文首行缩进两字符”而给标题再加缩进，也不得擅自删除模板标题缩进。
- 判断编号段是标题还是正文项时，综合使用章节作用、是否承担后文统领、同级样例、有效字重、终止标点和后续段落关系；不得只看长度或编号字符。分类有歧义时先人工复核，不运行全局缩进替换。

## 5.1 插入技术表格的角色与横向位置

固定表单与正文中的技术数据表必须分开处理。固定表单完全保持母版；插入的技术表格则建立一次性的 `technical_table` 角色，供本次全部同级技术表格复用。

技术表格外层位置按以下顺序确定：

1. 母版中同章节、同用途的技术表格原型；
2. 母版其他章节中同用途的技术表格原型；
3. 用户本次明确指定的对齐方式；
4. 母版没有同类实例时：可用宽度小于正文容器的紧凑技术表格采用流内居中，设置 `w:jc="center"` 并清除供体 `w:tblInd`；占满正文可用宽度的表格按容器宽度建立一致几何，不额外制造视觉左缩进。

供体的 `w:jc`、`w:tblInd`、浮动定位和环绕不构成目标格式依据。删除 `w:tblpPr` 让表格回到正文流之后，必须继续显式绑定 `technical_table` 的横向位置，不能把“没有 `w:jc`”留给编辑器默认解释。

整表居中不等于所有单元格文字居中。序号、短代码、日期和短数值通常按母版同类列居中；说明性长文本按母版同类列左对齐。表格宽度、网格、外边界中心与正文容器中心需要同时审计，不能只检查题注是否居中。

## 6. 格式验收

至少执行：

1. 先运行 `scripts/style_firewall.py TEMPLATE OUTPUT --json style-gate.json`，确认母版全局样式、主题和字体表未越界；
2. 再运行 `scripts/audit_template_format.py TEMPLATE OUTPUT --strict-table N --exact-unchanged-text`，对每个固定表单表格重复 `--strict-table`；未替换的模板原文必须整段 XML 不变；
3. 对位于顶层表格中的长正文，优先加 `--body-table N --body-prototype-regex '母版正文示例'`，由本次母版抽取完整缩进原型；仅在没有可用母版正文原型且用户明确给出数值时，才回退到 `--body-first-line-chars 200`。自动分类结果仍需结合章节角色复核，可用 `--body-exclude-regex` 排除模板特例；
4. 需统一参考文献西文字体及编号字重时，将母版或用户要求的实际值传给 --reference-latin-font 和 --reference-number-weight；不要把示例字体或字重当跨模板默认值；
5. 统计各角色的 `pPr/rPr` 指纹，异常指纹必须为零或有白名单；
6. 检查普通正文的 `firstLineChars`、列表缩进和参考文献字体；
7. 搜索段首空格、全角空格、NBSP、制表符、`w:spacing` 字距和分散对齐；
8. 母版、供体、合稿对应区域并排渲染，在目标编辑器中逐项核对。
9. 对每个允许新增内容的固定表单槽位，用 `--allow-value-cell TABLE:ROW:CELL` 显式登记，并用 `--value-run-prototype-cell TABLE:ROW:CELL` 指定母版中的共享正式值字符原型；目标单元格继续负责布局，共享正式值原型负责有效字体、字号、字重和正斜体。所有新增正式值必须通过这一角色检查，不能以“清除了说明斜体”为由保留说明字体或字号。
10. 对插入的每张技术表格记录有效 `w:jc`、`w:tblInd`、表格宽度和容器宽度；同级表格必须共享 `technical_table` 角色，紧凑表格的外边界中心与正文容器中心一致。

XML 一致而渲染不一致时，继续检查样式依赖、主题、字体替换、兼容设置和父容器；不能以“XML 中没有空格”结束排查。
